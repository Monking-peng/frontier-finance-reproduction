# Samaya FrontierFinance 系统性能基准复现研究（高度浓缩版）

## 结论先行

Samaya FrontierFinance 不是传统问答题库，而是一套用 11,543 条专家原子标准评估 220
个开放式投资研究任务的端到端系统基准。最难复刻的部分不是 grader——grader 和 rubric
都已公开——而是长程检索 Agent、时间截点控制、来源覆盖、运行成本以及裁判稳定性。

公开信息已经足以复刻完整的输入输出契约、Finance Agent v2 工具链、三裁判多数票、宏/
微指标、失败语义、结果文件和类似官网的展示页；不足以复刻 Samaya 私有模型、检索索引、
路由和缓存，也不足以声称获得官方榜单认证。

本项目已完成一条真实可执行链路。它从 Tesla 查询日前的 10-K/10-Q 内联 XBRL取数，
推导 Q4、完成勾稽、生成回答，再调用官方 `Grader` 与 `MetricsReport`。由于当前环境没有
三家 API key，裁判替换为透明确定性审计器，所以 87.5% 只是一条 Demo 的本地审计分，
不能与官网 50.8% 比较。

这次实跑还发现两个公开 rubric 数值冲突：`18.83bn` 实为 Q3 automotive sales；Q4 是
`18.659bn`。Q4 total automotive revenue 为 `19.798bn`，按官方精度规则应写 `19.8bn`，
不是 rubric 的 `19.7bn`。项目坚持用 SEC 数据并把两项判失败，说明可信 benchmark
工程必须允许“评分标准异常”成为一等故障，而不是只把所有失分归咎于模型。

## 系统链路

FrontierFinance 每条记录提供查询、query date、工作流标签、能力标签和一组 must-have /
nice-to-have rubric。回答系统看不到参考答案，因为没有参考答案；它必须从公开网页、SEC、
公司材料和市场数据中独立完成研究。公开基线分三类：模型厂商官方 Web Search API、带六
个金融工具的 Finance Agent v2、以及 Samaya 私有多模型与检索系统。

回答保存为 `[{query_id, system_summary}]`，再与 rubric JSONL 按 ID 连接。每条 rubric
由 Sonnet 4.6、Gemini 3.1 Pro、GPT 5.4 独立二元判断，逐条多数票。官网主分是逐查询
rubric 通过率的宏平均，而不是把全部 11,543 条直接 micro average。无回答按零分；某个
裁判失败就用存活票；三个都失败则视为 grader 异常并从分母排除。

## 对官网结果的解释

截至 2026-07-21，Samaya System 为 50.8%，Claude Fable 5 + Finance Agent v2 为
49.2%，GPT 5.6 Sol + Finance Agent v2 为 46.8%。这不能简化为“模型排行榜”：同一模型
换 harness 会显著改变质量、成本和延迟。成本又只计主 Agent 模型，不含搜索、数据索引和
grader，属于不完全成本。官网只给均值，也没有发布逐题回答与轨迹，因此外部只能验证
统计口径和公开代码，无法重新审计官方每个答案。

## 个人判断

这个基准最有价值的设计是把“完整性”显式化。传统 factuality 指标只检查说出来的话是否
有依据，却不惩罚遗漏；Criteria-Eval 用长尾 checklist 直接惩罚遗漏，非常适合金融研究。
代价是 rubric 本身成为新的模型：它会带入专家选择、数值错误、冗余和事后修订，需要版本、
来源证据和争议处理机制。

真正有工程价值的复现不应追求把某个数字抄到首页，而应做到三件事：第一，逐题锁定时间
边界，防止 hindsight leakage；第二，把模型、Agent、环境和评分异常分开；第三，让任何
分数都能回到具体回答、来源、工具轨迹、裁判票和哈希。本项目的后续扩展将以这三点作为
质量门槛。

## 尚未公开、不能伪造的部分

- Samaya 私有系统的内部提示词、模型、索引、路由和缓存；
- 官方 12 个系统的逐题回答、轨迹与每个裁判原始理由；
- 完整系统成本和延迟分布；
- 第三方提交到官方榜单的接口与审核流程；
- 官方提到但截至研究截点尚未发布的技术报告。

因此，当前最诚实的交付是一个可运行、可审计、可替换模型和裁判的复现框架，以及明确的
官方可比条件清单，而不是宣称已经复刻私有 Samaya 系统。
